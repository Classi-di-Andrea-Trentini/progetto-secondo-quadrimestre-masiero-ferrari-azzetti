# Project Overview

Common Era is a full-stack e-commerce application for a fashion brand. The name refers to the brand sold in the shop. The project is built as a learning exercise and covers the full cycle of a real online store: browsing products, managing a cart, placing orders, writing reviews, requesting returns, and managing an account.

## Stack

**Backend** — NestJS 11 running on Node 22. The API is a REST service that listens on port 3000. Prisma 7 handles all database access. The database is PostgreSQL 16.

**Frontend** — Angular 21 with server-side rendering enabled (Angular Universal via the built-in SSR support introduced in v17). Components are all standalone — there are no NgModules in the application code. State is managed with Angular signals. The app runs on port 4200.

**Infrastructure** — Three Docker containers orchestrated with Docker Compose. There is no reverse proxy in the current setup; frontend and backend are accessed directly on their ports. The Postgres data directory is persisted in a named volume called `pgdata`.

## Running the project

Everything runs inside Docker. No local Node installation is needed to run the app.

```bash
docker compose up -d                        # start all three containers
docker compose restart backend              # pick up backend code changes
docker compose restart frontend             # pick up frontend code changes
docker compose logs backend --tail=50       # check backend output
docker compose logs frontend --tail=50      # check frontend build errors
```

The frontend container runs `ng serve` in watch mode, so file changes inside `e-commerce/src` are picked up automatically without a restart. The backend container also runs in watch mode (`nest start --watch`), but a restart is sometimes needed after adding a new module.

## Environment variables

The backend reads from `server/.env` (mapped via `env_file` in docker-compose). The file is not committed. The variables are:

```
DATABASE_URL=postgresql://user:password@db:5432/mydb
JWT_SECRET=...
FRONTEND_URL=http://localhost:4200
BACKEND_URL=http://localhost:3000
RESEND_API_KEY=...
RESEND_SENDER_EMAIL=...
RESEND_SENDER_NAME=...
```

In development the `RESEND_API_KEY` can be left empty. The mail service will log the email content to the console instead of sending it.

## Database access

```bash
# run a SQL file against the database
docker compose exec -T db psql -U user -d mydb < database/init/001_schema.sql

# open an interactive psql session
docker compose exec db psql -U user -d mydb

# regenerate the Prisma client after schema changes
docker compose exec backend npx prisma generate

# create a new migration
docker compose exec backend npx prisma migrate dev --name describe_the_change
```

The schema lives in `server/prisma/schema.prisma`. All primary keys are UUIDs generated by PostgreSQL's `gen_random_uuid()` function. `Decimal` fields are serialized by Prisma as strings in JSON responses, so the frontend always calls `parseFloat(String(value))` before doing any arithmetic.
